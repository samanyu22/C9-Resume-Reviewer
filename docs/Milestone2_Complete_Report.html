Section 2: Prompt and Solution Design

2.1 Solution Overview & Design Decisions

Problem & Target Users: College students and fresh graduates applying for internships often struggle to understand how well their resumes match job descriptions. They receive opaque automated rejections without actionable feedback on missing skills, weak bullet points, or how to align their experiences. Concurrently, recruiters face massive applicant volumes and need transparent, explainable evaluations rather than arbitrary black-box scores.

Input & Output: Inputs are raw resume text (PDF/DOCX) and the company job description. Outputs are: (1) a structured requirement match matrix with verified evidence quotes, (2) an explainable 0–100 compatibility score across 6 weighted dimensions, and (3) action-oriented STAR-format bullet point suggestions grounded strictly in candidate actual experience.

Decomposition Strategy (Why 3 Prompts): Our Milestone 1 baseline used a single monolithic prompt. Testing revealed severe score variance (σ = 8.6), hallucinated tools, and frequent JSON syntax errors. Decomposing the system into 3 specialized stages (P1_PARSER → P2_SCORER → P3_REWRITER) isolates entity extraction from mathematical scoring and creative rewriting, eliminating cognitive overload in the model.

Tool and Model Choice: Gemini 2.5 Flash via Google AI Studio was selected for its high reasoning capabilities, native JSON schema support, low latency (<1.5s per turn), and extensive context window.

3.1 Module Status Table

1. Resume & JD Entity Extractor Parses raw text; extracts normalized skills, experience, education; types requirements. Working Uses P1_PARSER ($T=0.1$); 100% valid JSON schema output.
2. Hybrid Match & Scoring Engine Computes 6-part weighted formula ($0.40 \cdot \text{Skills} + \dots$); extracts quotes; flags gaps. Working Uses P2_SCORER ($T=0.1$); deterministic inter-run variance $\Delta = 0.0$.
3. Resume Bullet Point Rewriter Transforms weak bullets into STAR-format achievements without fabricating facts. Working Uses P3_REWRITER ($T=0.2$) with 2 few-shot demonstration examples.
4. AI Interview Question Generator Generates dynamic technical verification questions based on identified candidate gaps. Partly Working Prompt tested in AI Studio; full voice/audio state machine planned for Milestone 3.

3.2 Prompt Iteration Log

Version What changed Why it was changed Result after the change
v1 Initial monolithic prompt asking to compare resume, give 0-100 score, list gaps, and rewrite bullets. Milestone 1 baseline starting point. High variance: Scores on identical input drifted between 58/100 and 85/100 (σ = 8.6); hallucinated AWS/Tableau; unparseable plain text.
v2 Added 6-part weighted mathematical rubric, mandatory vs preferred typing, and raw JSON schema. Subjective scoring had no auditability; frontend required structured data. Score stabilized, but format broke: Score variance dropped to ±3.2. However, markdown backticks broke JSON parsing in 3 out of 10 runs.

JSON parsing crashes; need for zero hallucination and clear separation of extraction, math, and rewriting. 100% reliable execution: Valid JSON in 10 out of 10 runs (0 parser errors). Zero hallucinated skills. Score variance on identical inputs dropped to 0.0 difference.

4.2 Error Analysis on Failed Tests

Test 8 (Hinglish Failure): When presented with code-mixed vernacular, the model correctly identified technical entities but mirrored the candidate's conversational dialect in its output explanation. Fix for M3: Implement a pre-LLM language routing rule and enforce OUTPUT_LANGUAGE: STRICT_ENGLISH.

Test 10 (Single-word "idk" Failure): Generative LLMs exhibit positive completion bias, attempting to extract meaning from noise. Fix for M3: Implement a deterministic character length guard (≥ 150 characters) prior to LLM invocation.

4.3 Known Limitations & Next Steps

1. Multi-Column PDF Flattening: Standard parsers scramble 2-column resumes. Next Step: Introduce bounding-box OCR in Milestone 3.

2. Pipeline Latency: 3 sequential calls require 4.5–7.0s. Next Step: Concurrently execute P2 and P3 after P1 resolves.

3. Floating-Point Precision: Models occasionally make minor rounding errors. Next Step: Move final weighting to deterministic backend math.

Executive Summary: Manual resume screening creates operational bottlenecks, while opaque scoring algorithms alienate applicants.
